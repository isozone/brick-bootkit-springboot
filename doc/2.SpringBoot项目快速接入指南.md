# Spring Boot 项目快速接入指南

## 最短接入路径

适用于一个已有的 Spring Boot 3.x 项目，希望尽快接入插件能力。

### 1. 引入依赖

```xml
<dependency>
    <groupId>com.zqzqq</groupId>
    <artifactId>spring-boot3-brick-bootkit</artifactId>
    <version>4.0.6</version>
</dependency>
```

如果还需要插件 Web 管理台，再额外引入：

```xml
<dependency>
    <groupId>com.zqzqq</groupId>
    <artifactId>spring-boot3-brick-bootkit-web</artifactId>
    <version>4.0.6</version>
</dependency>
```

### 2. 保持启动类是标准 Spring Boot 启动类

```java
@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

框架会通过 Spring Boot 的自动配置机制自动接入，通常不需要再手工扫描 `com.zqzqq.bootkits`。

### 3. 添加最小配置

```yaml
plugin:
  enable: true
  runMode: prod
  pluginPath:
    - ./plugins
```

### 4. 关于 `plugin.mainPackage`

现在对于标准 Spring Boot 项目，框架会优先自动推断主应用包名。

只有在以下场景，才建议显式配置：

- 启动类不在宿主项目根包
- 使用了比较特殊的多模块扫描结构
- 宿主项目不是标准 `@SpringBootApplication` 启动方式

显式配置示例：

```yaml
plugin:
  mainPackage: com.example.demo
```

### 5. 如需启用 Web 管理台

```yaml
plugin:
  web:
    enabled: true
    enable-ui: true
```

默认页面入口：

```text
http://localhost:8080/plugins-web/
```

### 6. 使用 doctor 自检环境

第一次接入完成后，建议直接执行一次环境自检：

```text
GET /plugins-web/api/doctor
```

自检报告会告诉你：

- 主应用包名是否已自动推断成功
- 插件目录是否存在、是否可读
- 上传临时目录是否可写
- 当前发现了多少个插件
- 当前有哪些错误和告警需要处理

## 推荐接入顺序

1. 先只接入 `spring-boot3-brick-bootkit`
2. 确认宿主项目能正常启动
3. 再配置 `pluginPath` 并放入插件包验证加载
4. 最后再接入 `spring-boot3-brick-bootkit-web`

## 常见坑

- `pluginPath` 最好使用明确目录，不要依赖模糊相对路径
- 开发环境和生产环境的插件目录建议分开
- 如果启用了 Web 管理台，生产环境必须提供宿主侧 `PluginWebAuthorizer`
- 如果项目启动时报主包配置问题，先检查启动类包结构，再考虑显式配置 `plugin.mainPackage`
