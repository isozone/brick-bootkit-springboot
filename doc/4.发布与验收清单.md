# 发布与验收清单

## 📋 概述

本页不是“发布流程图”，而是每次发版前最小必须过一遍的检查清单。过不齐就先别发，先把缺口补上。

## ✅ 最小发布检查

- [ ] `git diff --check` 通过（无空白错误、无冲突标记残留）
- [ ] 关键模块测试通过：`loader / core / spring-boot3-brick-bootkit` 单测绿
- [ ] README / docs-website / 更新日志已同步当前版本号
- [ ] 最小模板和故障模板内容已对齐当前版本（`templates/` 下 host / plugin 各模板可正常引用最新坐标）
- [ ] 首页 doctor 摘要和上传向导可正常工作
- [ ] `pom.xml` 父工程与各模块 `<version>` 一致，无残留旧版本号
- [ ] `.publish-version` 锚点已更新为本次发布版本

## 🤖 自动化预检脚本

- `release-precheck.sh`：Linux / macOS 下的汇总预检脚本，覆盖 git diff、模板存在性、关键文档存在性、稳定模块测试
- `release-precheck.ps1`：Windows 下的汇总预检脚本，与 sh 版行为对称

发版前在本地对应平台跑一次，全绿后再走真实发布流程。

## 🚀 发布流程参考

发布到 Maven 中央仓库使用项目根下的发布脚本：

- Windows：`publish.bat`
- macOS / Linux：`publish.sh`

均支持：
- `--check`：仅校验 release profile，不真实发布
- `--version <x.y.z>`：手动指定发布版本（默认从根 pom 当前版本 bump patch）

账号与签名通过环境变量或 `settings.xml` 的 `<server>` 配置注入：

- `MAVEN_SETTINGS`：指定 settings.xml 路径
- `CENTRAL_USERNAME` / `CENTRAL_PASSWORD`：Central Portal 账号
- `GPG_KEYNAME`：GPG 签名密钥 ID

## 🔄 发布后动作

1. 脚本会自动把 pom 版本回滚到 `<新版本>-SNAPSHOT` 开发态
2. 脚本会写入 `.publish-version` 锚点，下次执行自动递增
3. 等待 Maven Central 同步（通常 30 分钟 ~ 2 小时）
4. 在 `doc/updates/` 下补本次版本的更新日志
5. 打 GitHub Release Tag，附上中央仓库已发布的坐标

## ⚠️ 常见问题

- **`gpg: signing failed`**：确认 `gpg --list-keys` 能看到密钥，且 `settings.xml` 里 `serverId=gpg` 的 passphrase 已配
- **`central publishing rejected`**：确认 Central Portal 上当前 `com.zqzqq` namespace 处于 `Published` 状态，非 `Pending` 首次验证
- **`versions:set 报 You must specify the new version`**：Windows cmd 下 `-DnewVersion=x.y.z` 必须加引号 `"-DnewVersion=x.y.z"`，否则 cmd 会把 `.z` 当路径扩展吃掉
