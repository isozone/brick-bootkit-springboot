# 4.0.10 更新日志

## 🚀 新能力（2026-08）

本版本聚焦**分布式插件模块的可观测性、运维体验与长连接稳定性**，是对 4.0.9 分布式基线的
增量增强。所有改动默认向后兼容，无需修改任何配置即可升级。

### 1. 分布式可观测性：管理端点（方向一收尾）

新增 Web 控制台分布式状态端点，把原本只活在 JVM 内存与 WARN 日志里的运行时状态
（failover 计数、节点健康、Redis 兜底命中、远端调用耗时等）变成「可观察、可告警、可前端展示」。

- **新增端点**：`GET /monitor/distributed`
  - 未启用分布式模块时返回 `{disabled: true, message: ...}`，与「指标全零」明确区分
  - 已启用时聚合 `DistributedStatus` 全字段：
    `role / nodeId / remoteCalls / errorRate / failoverCount /
     circuitBreakerTripped / avgCallMillis / activeChannels /
     registryAvailability / nodes / registeredServiceInterfaces`
  - 复用 `PluginWebPermission.PLUGIN_VIEW` 权限，与现有监控端点一致
- **解耦设计**：web 模块通过 `ObjectProvider<DistributedStatusProvider>` 注入，
  distributed 模块作为 `provided + optional` 依赖引入——web 可独立编译/打包，
  分布式模块按需启用，零侵入。

### 2. gRPC keepAlive 与 idle 超时（方向四）

跨 NAT/公网/容器网络时长连接可能被中间设备静默断开，客户端无感知的情况下
首次真实调用会吃一次完整超时。本版本显式开启 keepAlive，让 gRPC 在空闲期
主动探测、尽早发现死连接。

- **客户端**（`GrpcClientProvider`）：
  - `keep-alive-time-millis`（默认 60000）：keepAlive ping 间隔，<=0 关闭
  - `keep-alive-timeout-millis`（默认 20000）：ping 等待 ACK 超时
  - `keep-alive-without-calls`（默认 true）：无活跃调用时也发 ping
- **服务端**（`GrpcServerBootstrap`）：
  - `keep-alive-time-millis`（默认 60000）：服务端主动 ping 间隔
  - `permit-keep-alive-time-millis`（默认 30000）：允许客户端 ping 的最小间隔
    （低于该值会被服务端拒绝并关闭连接，防御恶意/失控客户端高频 ping）
  - `permit-keep-alive-without-calls`（默认 true）：允许客户端无活跃调用时 ping
- 默认值与 gRPC 官方推荐对齐；旧构造链全部保留并委托到新全参构造，**向后兼容**。

### 3. 错误响应携带节点信息与耗时（方向三）

业务异常（远端节点本身健康，仅业务侧抛错）的错误响应现在也携带节点信息，
方便排障——此前只有传输层失败路径会带节点 host:port + 耗时。

- **实现**：新增 `RemoteInvocationHandler.RemoteInvocationContext`，
  挂在原业务异常的 `Throwable.suppressed` 链上，携带
  `host / port / nodeElapsedMillis / totalElapsedMillis`。
- **关键设计**：
  - **不**用反射改 `Throwable.detailMessage`（JDK 17+ 强模块化会失败）
  - **不**改异常类型（调用方仍可 `catch (IllegalStateException)` 等原始业务异常类型）
  - **不**改异常 message（保持业务语义不被污染）
  - 调用方通过 `Throwable.getSuppressed()` 即可拿到排障所需的节点 + 耗时上下文
- 业务异常路径**不触发 failover**（节点本身健康，无需切换副本）

## 🐛 Bug 修复

### 1. 整组重试 `groupAllUnavailable` 死代码（中等）

- **位置**：`RemoteInvocationHandler.invokeRemoteWithFailover`
- **症状**：`groupAllUnavailable` 变量声明后从未被改成 `false`，
  导致 `if (!groupAllUnavailable) break;` 是死代码，整组重试逻辑退化——
  一旦开启 `max-failover-retries`，即便所有节点都在熔断 OPEN 窗口里被短路跳过、
  没真去发网络调用，也会无意义地退避重试 20ms+40ms+...，把失败调用耗时白白拉长。
- **修复**：改用 `anyRealAttempt && anyUnavailable` 双标志位精确描述本轮真实情况，
  仅当本轮真发了网络调用且有节点返回 UNAVAILABLE 时才认为「整组不可达」触发退避重试。
- **回归测试**：新增 `RetryRoundSemanticsTest#shouldNotRetryWhenAllNodesShortCircuitedByBreaker`，
  构造唯一节点已被熔断的场景，断言修复后调用耗时 < 15ms（旧死代码至少退避 20ms+）。

### 2. `@PreDestroy` 未关闭 `GrpcClientProvider`（中等，资源泄漏）

- **位置**：`DistributedPluginAutoConfiguration.destroy()`
- **症状**：只关了 `serverBootstrap` 和 `registrationScheduler`，没关 `clientProvider`，
  客户端持有的所有 ManagedChannel 在 Spring 容器销毁期间一直保持打开，直到 JVM 退出
  才回收——热重启/上下文刷新场景下会留下 socket 泄漏。
- **修复**：持有 `clientProvider` 字段，`destroy()` 按
  「先停注册 → 关服务端 → 关客户端」顺序关闭，保证优雅停机期间宿主侧在途调用
  有机会先完成。

## ⬆️ 升级注意

- **零配置升级**：本版本所有新能力均使用与 gRPC 官方推荐一致的默认值，
  无需修改任何配置即可获得 keepAlive 稳定性提升与可观测性端点。
- **显式调参场景**：跨 NAT/公网部署如需自定义 keepAlive 间隔，可通过
  `plugin.distributed.keep-alive-time-millis` 等配置项调整；
  想保留旧版「不显式设置 keepAlive」的语义可设为 `<=0` 关闭。
- **API 兼容**：所有现有构造器、配置项、对外 API 保持向后兼容。
