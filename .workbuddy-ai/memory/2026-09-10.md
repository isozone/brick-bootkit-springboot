# 2026-09-10

## 存量项目接入三件套（痛点方向：旧项目如何快速接入）

起因：用户提出痛点"旧项目如何快速接入本框架"。分析后定位到四个阶段
（可行性 / 依赖引入 / 启动适配 / 业务切片），框架此前只覆盖阶段 2、3，
阶段 1 和 4 完全空白。按用户要求依次实现 A → B → C。

### A. preflight 离线体检器（`tools/preflight/`）
- `Preflight.java` 零依赖单文件 + `preflight.sh`，JDK 单文件源码模式运行。
- 检查项 `PF001..PF040`，退出码 0/1/2，支持 `--json`。
- 文档：`doc/8.旧项目渐进式接入指南.md`。
- 关键坑：pom 里的 `${spring-boot.version}` 必须递归解析 properties；
  启动类识别要用行首锚定正则 `(?m)^[ \t]*@(SpringBootApplication|...)`，
  否则注释/字符串里的文本会误报；多模块要按 `<modules>` 收敛，否则 templates/ 会被扫进来。

### B. 渐进式接入级别
- 新增 `AdoptionLevel` 枚举（SHADOW/OBSERVE/ACTIVE），
  `IntegrationConfiguration` 增 `autoLoadPlugins` / `autoStartPlugins` / `adoptionLevel()` 默认方法。
- 拦截点在 `DefaultPluginOperator#initPlugins`；doctor 增 `ADOPTION_LEVEL_*` 警告。
- 向后兼容：两个开关默认 true = 原全量行为。
- **Mockito 坑**：mock 接口时默认方法返回 `null`，doctor 里必须判空，
  否则既有 `PluginDoctorServiceTest` 会 NPE。已加 `shouldTolerateNullAdoptionLevelFromLegacyConfiguration` 用例。
- 测试：`AdoptionLevelTest`(6) + `PluginDoctorAdoptionTest`(4)，全绿。

### C. 业务切片分析器（`tools/slicer/`）
- `SliceAnalyzer.java` 零依赖单文件 + `slice.sh`，参数 `--json / --top N / --depth N`。
- 选型：源码文本解析（非 ASM 字节码），换取"项目能编译之前就能跑"；精度边界写进文档。
- 指标：fanIn / fanOut / 外部库组 / 对外契约类 / 循环依赖；评分初始 60 分再按耦合惩罚。
- 文档：`doc/9.业务切片分析指南.md`。
- 调试中修掉的真问题：
  1. `autoDepth` 用严格公共前缀会被单个离群包打成 0（深度退化到 1，742 个类挤进一个 `com` 包）
     → 改为按类数量加权的 80% 多数表决。
  2. 契约类用"引用次数"没有区分度 → 改为"被几个包引用"。
  3. 循环依赖段曾把 fanIn 当"互相依赖包数"用（措辞错误）→ 改为计算真正的双向伙伴 `cyclePartners`。
  4. 全量扫描会把 templates/、web-demo 当业务代码 → 按根 pom `<modules>` 收敛扫描起点。
  5. 小项目误报"包结构扁平" → 按规模/共享层/扁平三种原因分别给提示。

## D. 插件骨架生成器（`tools/scaffold/`）
- `ScaffoldGenerator.java` + `scaffold.sh`，CLI: `<项目路径> <包名> [输出目录] [--force]`。
- 内部调用 slicer 获取 JSON，基于候选包生成完整插件模块：
  - pom.xml（含 brick-bootkit-maven-packager、自动推断的依赖）
  - `*PluginBootstrap.java`（继承 `SpringPluginBootstrap`）
  - `*PluginInfo.java`（实现 `PluginInfo`）
  - `api/*.java`（契约接口，从 contractClasses 提取方法签名）
  - `plugin/*ServiceImpl.java`（业务 stub，TODO 标记）
  - `spring.factories`
- 关键技术点：
  1. 接口方法可能和 `interface` 声明在同一行（`{ String build(); }`），
     `INTERFACE_METHOD` 正则不能锚定行首，需用 `(?<![\w.])` 负向回顾避免误匹配 import。
  2. 契约类（在 `contractClasses` 中）已在 `api/` 生成接口，不再在 `plugin/` 重复生成服务 stub。
  3. 方法提取跳过 getter/setter/toString/equals/hashCode/构造方法，减少噪音。
- 文档：`doc/10.插件骨架生成器.md`；已接入 README / doc/8 / doc/9 / ROADMAP。

## F. doctor 增强： adoption-level 感知的插件计数
- `PluginDoctorService#buildNoPluginItem`：根据当前接入级别给出差异化的"无插件"提示：
  - L0 影子模式 → OK（符合预期，未读取目录）
  - L1 观察模式 + 目录为空 → OK（尚未放入插件包）
  - L1/L2 + 目录有文件但 0 个插件 → WARN（解析/校验失败，需看日志）
  - L2 + 目录为空 → WARN（配置或部署问题）
- 新增 `countPluginFiles`：扫描 `plugin.pluginPath` 下 `.jar`/`.zip` 文件数量。
- 测试：`PluginDoctorServiceTest`(2) + `PluginDoctorAdoptionTest`(4) 全绿。

## E. 统一迁移向导（`tools/migrate/`）
- `migrate.sh`：bash 串联脚本，一键完成 `preflight → slicer → scaffold`。
- 支持 `--auto`（自动选评分最高候选包）和 `--force`（覆盖输出）。
- 有阻断项时第一步就停止并打印问题清单；无阻断项则继续切片分析和骨架生成。
- 完成后自动输出 `application.yml` 配置建议和 L0/L1/L2 验证顺序。
- 文档：`doc/11.统一迁移向导.md`；已接入 README / ROADMAP。
- smoke 测试新增 7 条断言（合规项目全链路通过、阻断项目提前停止）。

## 新增 tools 自检脚本
- `tools/test/smoke.sh`：零依赖 bash，生成临时 fixture（ok / blocked / monolith / empty），
  对 preflight 与 slicer 做 22 条断言覆盖（exit code、JSON 结构、候选排序、共享层识别、循环依赖、空目录处理）。
  **已知陷阱**：bash `((VAR++))` 在 `VAR=0` 时表达式值为 0（假），`set -e` 会直接终止脚本；
  必须用 `VAR=$((VAR + 1))` 或 `((++VAR))`。
